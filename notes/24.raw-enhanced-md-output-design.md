# 24. raw/enhanced 双 md 输出设计方案

## 背景

当前增强模式下，`{name}.md` 直接输出增强后内容，原始 md 丢失。
需要：原始 md 与增强 md 分开输出，并统一 CLI/API 的控制参数。

---

## 一、文件命名（最小改动，向后兼容）

| 文件 | 何时写出 |
|------|---------|
| `{name}.md` | **始终写出**（原始 raw markdown） |
| `{name}_enhanced.md` | 仅当 enhance_enable=True 且 `output_md ∈ {enhanced, both}` |
| `{name}_enhance.json` | 同上，与 `_enhanced.md` 联动 |

---

## 二、`output_md` 参数语义

取值 `"auto" | "raw" | "enhanced" | "both"`

| 值 | 写 raw md | 写 enhanced md | 运行 LLM pipeline |
|----|-----------|---------------|-----------------|
| `"auto"`（默认）| ✅ | 取决于 enhance_enable | 取决于 enhance_enable |
| `"raw"` | ✅ | ❌ | ❌（跳过） |
| `"enhanced"` | ✅ | ✅ | ✅ |
| `"both"` | ✅ | ✅ | ✅ |

**智能推断**：`output_md="auto"` 时，在 `_process_output` 内根据 `enhance_enable` 推断：
- `enhance_enable=True` → 等同 `"enhanced"`
- `enhance_enable=False` → 等同 `"raw"`

---

## 三、CLI 参数设计

### 移除
- `--md-only`：直接删除，不保留 alias

### `--output-md` 参数（已落地）

```
--output-md [auto|raw|enhanced|both]
```

**设计语义**：传入 `--output-md`（无论何值）时，输出目录**只保留 md 文件**，不包含 middle.json、model.json、layout、images 等重量产物。具体输出哪个 md 由值决定：

| 用法 | output_md 值 | 说明 |
|------|-------------|------|
| 不传 `--output-md` | `"auto"` | 默认行为，md-only 模式 |
| `--output-md`（无参数）| `"auto"` | 当 flag 用，等同默认 |
| `--output-md auto` | `"auto"` | 显式指定，智能推断 |
| `--output-md raw` | `"raw"` | 只输出原始 md，跳过 LLM |
| `--output-md enhanced` | `"enhanced"` | 只输出增强 md（LLM 未启用时 fallback 到 raw） |
| `--output-md both` | `"both"` | 同时输出 raw + enhanced md |

**实现要点**：
- Click 定义使用 `is_flag=False, flag_value="auto"`，支持无参数当 flag 使用
- `_enhance.json` 在 md-only 模式下**永远不写入** ZIP，属于内部 pipeline 产物
- `enhanced` / `auto` 模式若 enhanced.md 不存在，自动 fallback 到 raw.md

**`run_enhancement` 触发条件**（`common.py`）：
```python
run_enhancement = enhance_enable and effective_output_md in ("auto", "enhanced", "both")
```
注意：`"auto"` 必须包含，否则默认模式下 LLM 不会运行。

---

## 四、API 层参数设计

### 移除
- `return_md: bool`
- `return_enhance_json: bool`（与 enhanced md 联动，不再单独控制）

### 新增
- `return_md_raw: bool`：响应中包含 `{name}.md`
- `return_md_enhanced: bool`：响应中包含 `{name}_enhanced.md` + `{name}_enhance.json`
- `output_md: Optional[str]`：优先于 `return_md_raw/return_md_enhanced` 的 md 选择逻辑

### `output_md` 在 server 侧的推导规则（向后兼容）
```python
# output_md 直接传入时优先使用；否则根据旧 flag 推导
if request_options.output_md is not None:
    output_md_value = request_options.output_md
elif return_md_raw and return_md_enhanced:
    output_md_value = "both"
elif return_md_enhanced:
    output_md_value = "enhanced"
elif return_md_raw:
    output_md_value = "raw"
else:
    output_md_value = None
```

### `create_result_zip` 文件选择逻辑
```python
if output_md is not None:
    # md-only 模式：_enhance.json 永远不包含
    if output_md in ("auto", "enhanced"):
        包含 enhanced.md（不存在则 fallback 到 raw.md）
    elif output_md == "raw":
        包含 raw.md
    elif output_md == "both":
        包含 raw.md + enhanced.md
else:
    # 全量模式（旧行为）：根据 return_md_raw/return_md_enhanced 控制
    # return_md_enhanced=True 时包含 enhanced.md + enhance.json
```
