# middle.json 中 para_blocks / preproc_blocks / discarded_blocks 解析

## 生命周期顺序

```
ML 推理输出
    ↓
MagicModel.__build_return_blocks()
    ├── preproc_blocks   ← 未被 discard 的块（原始 ML 输出，未合并）
    └── discarded_blocks ← 被 DiscardPolicy 过滤的块（header/footer 等）
    ↓
para_split()（全部页面处理完后统一执行）
    └── para_blocks      ← 对 preproc_blocks 做段落合并后的结果
```

---

## 三者区别

| | `preproc_blocks` | `para_blocks` | `discarded_blocks` |
|---|---|---|---|
| **来源** | ML 检测直接分类后 | preproc_blocks 经段落合并 | ML 检测 + DiscardPolicy 过滤 |
| **阶段** | MagicModel 初始化时 | para_split() 后处理时 | MagicModel 初始化时 |
| **文本块** | 每个检测区域独立一块 | 相邻文本块按启发式规则合并 | 不合并 |
| **块数量** | 较多（未合并） | 较少（合并后） | 取决于 discard 策略 |
| **schema** | 相同（lines/spans/bbox） | 相同 | 相同 |

---

## 合并规则（preproc → para）

`para_split.py` 的合并条件：
- 上一块末行不以句号/感叹号等结尾
- 下一块首字非大写/数字
- 两块宽度差在阈值内、左对齐一致

合并方式：`block2['lines'].extend(block1['lines'])`，原来两个独立文本块变成一个。同时对 TEXT/LIST/INDEX 做重新分类。

---

## 各自用途

**`preproc_blocks`**：
- `draw_span_bbox` 用它 → 可视化**原始 ML span 级别**检测（合并前）
- middle.json 保留它 → 审计追踪、不重新推理就能重新处理

**`para_blocks`**：
- `draw_layout_bbox` 用它 → 可视化**最终语义段落**布局
- 所有内容生成（markdown / content_list / content_list_v2）用它

**`discarded_blocks`**：
- `draw_layout_bbox` 用它 → 用灰色画出被丢弃的区域
- `union_make` 合并时会把它追加到 para_blocks 后面 → content_list 里包含完整位置信息（供下游分析）
- middle.json 保留 → 某些场景下 header/footer 有用（如文档元信息提取）

---

## 关键结论

`preproc_blocks` 是**原始 ML 检测快照**，`para_blocks` 是**面向阅读的语义段落**，两者 schema 完全一致，区别仅在于文本块是否做了合并。`discarded_blocks` 是**被策略剔除但保留以备用**的块，content_list 生成时会重新纳入，markdown 生成时则完全排除。
