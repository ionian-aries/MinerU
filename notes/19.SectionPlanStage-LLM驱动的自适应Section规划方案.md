## 1. 背景与设计动机

### 1.1 旧方案问题（notes/13 + 旧 SectionPlanStage）

旧方案依赖两层设计：

1. **SectionBuildStage**：遍历 content_list_v2，基于 title 层级构建 `SectionNode` 树
2. **SectionPlanStage**：对 SectionNode 树做 LLM 驱动的节点合并

这带来以下问题：
- `SectionNode` 树结构复杂，`seq_id`/`after_seq_id`/`block_ref` 等关联字段冗余
- `BlockRef` dataclass 封装多余（数据只是三元引用）
- 空 BodyItem 噪音（多个连续 title 之间插入 `char_count=0, block_refs=[]` 的占位体）
- `seq_id` 存储在 TitleItem 字段中，而数组位置本身已提供该信息
- `after_seq_id` 存储在 BodyItem 字段中，而列表中前一个 TitleItem 已隐含该关系

### 1.2 新方案核心原则

> **数组顺序即文档顺序，位置关系不需要存储在字段里。**

- `BlockIndexer`：直接输出 `list[TitleItem | BodyItem]`，顺序即文档物理顺序
- 无 `seq_id`、无 `after_seq_id`、无 `BlockRef` dataclass
- block_refs 为三元列表 `[page_no, block_no, type]`，1-based（与 content_list_v2 外层 page_idx + 内层 block_idx 枚举对应）
- 空 BodyItem（无 block_refs 且 char_count=0）不发射，消除噪音

## 2. Stage 1: BlockIndexer（`stages_block_indexer.py`）

### 2.1 数据结构

```python
@dataclass
class TitleItem:
    title_text: str
    block_ref: list   # [page_no_1based, block_no_1based, "title"]

@dataclass
class BodyItem:
    char_count: int = 0
    preview: str = ""
    block_refs: list[list] = field(default_factory=list)  # [[page_no, block_no, type], ...]
    body_text: str = ""
```

**移除字段**：`TitleItem.seq_id`、`BodyItem.after_seq_id`、`BlockRef` dataclass

### 2.2 block_refs 编码规则

content_list_v2 结构：`content_list_v2[page_idx][block_idx]`（均 0-based）

BlockIndexer 中转换为 1-based：

```python
block_ref = [page_idx + 1, block_idx + 1, block_type]
```

索引语义：`ref[0]` = 页码，`ref[1]` = 块号，`ref[2]` = ContentTypeV2 类型字符串。

### 2.3 扫描算法

```
遍历 content_list_v2[page_idx][block_idx]:
  skip_types 中的块 → 跳过
  "title" 块       → emit_body_if_nonempty(current_body); append TitleItem; current_body = BodyItem()
  文本类块          → current_body.block_refs.append; 提取文本到 body_text
  视觉类块          → current_body.block_refs.append; 可选 caption 加入 body_text
  其他类块          → current_body.block_refs.append（防御性保留）

扫描结束            → emit_body_if_nonempty(current_body)
```

**`_emit_body_if_nonempty`**：仅当 `body.block_refs` 非空或 `body.char_count > 0` 时才 append。
效果：多个连续 title → 连续 TitleItem，中间无空 BodyItem。

### 2.4 输出示例（FZ/T 73020-2019 前几页）

```
BodyItem(char_count=17, preview='ICS 59.080.30\nW63', block_refs=[[1,1,'index']])     ← preamble
TitleItem(title_text='中华人民共和国纺织行业标准', block_ref=[1, 2, 'title'])
BodyItem(char_count=80, preview='FZ/T 73020—2019\n代替FZ/T73020—2012…', block_refs=[[1,3,'paragraph'],[1,4,'paragraph'],[1,5,'paragraph'],[1,6,'paragraph'],[1,7,'paragraph'],[1,8,'paragraph']])
TitleItem(title_text='中华人民共和国纺织', block_ref=[2, 1, 'title'])
TitleItem(title_text='行业标准', block_ref=[2, 2, 'title'])       ← 连续 title，无空 BodyItem
BodyItem(char_count=280, preview='针织休闲服装\n...', ...)
TitleItem(title_text='前 言', block_ref=[3, 1, 'title'])
BodyItem(char_count=1456, ...)
...
```

### 2.5 `_finalize_body` — preview 截取策略

preview 基于 `body_text.strip()` 计算，保留原始换行（`body_text` 不做换行处理，换行仅在 flat_table 构建时由 `_format_refs` 的消费方处理）：

```python
def _finalize_body(body: BodyItem) -> BodyItem:
    text = body.body_text.strip()
    if not text:
        body.preview = ""
    elif len(text) <= 50:
        body.preview = text            # 全文
    elif len(text) <= 200:
        body.preview = text[:50] + "…" + text[-50:]   # 首 50 + 尾 50
    else:
        body.preview = text[:80] + "…" + text[-80:]   # 首 80 + 尾 80
    return body
```

**截取阈值**（对称首尾采样）：

| 文本长度 | 策略 |
|---------|------|
| 0 | `""` |
| ≤ 50 | 全文 |
| ≤ 200 | 首 50 + `…` + 尾 50 |
| > 200 | 首 80 + `…` + 尾 80 |

### 2.6 build_skip_set()

`_ALWAYS_SKIP_V2`（页眉/页脚/页码/旁注/脚注）∪ `custom_config.discard.types` 映射。

`custom_config.discard.types` 存储 BlockType（middle_json 层），需通过 `_BLOCK_TYPE_TO_CONTENT_TYPE_V2` 映射到 ContentTypeV2。

## 3. Stage 3: SectionPlanStage（`stages_section_plan.py`）

### 3.1 `_parse_items()` — flat list 到位置关联

消费侧不依赖任何存储在 item 中的 id 字段：

```python
def _parse_items(items):
    title_items = []
    body_map = {}      # title_idx（0-based） → BodyItem
    preamble = None
    title_idx = -1

    for item in items:
        if isinstance(item, TitleItem):
            title_idx += 1
            title_items.append(item)
        elif isinstance(item, BodyItem):
            if title_idx < 0:
                preamble = item       # 首个 title 前的内容
            else:
                body_map[title_idx] = item  # 紧跟在 title_items[title_idx] 后
    return title_items, body_map, preamble
```

### 3.2 LLM flat table 格式（四列结构）

格式设计原则：
- **第一列 `type`**：`title[NN]` 或 `body`，立即标识行语义
- **第二列 `"text/preview"`**：双引号包裹；title 行为原始标题文本，body 行为 `_finalize_body` 生成的首尾预览
- **第三列 `chars`**：统一整数；title = `len(title_text)`，body = `char_count`（正文字符数，不含图表）
- **第四列 `refs`**：`页码,块号,类型` 三元组，多个用 `; ` 分隔，无括号

**NN = `enumerate(title_items)` 的 0-based 位置，直接对应输出 `seq_ids` 整数，两位补零。**
**body 行无序号**——位置隐含归属（紧跟其前一个 title），LLM 可从位置推断，无需冗余标注。

表头行固定为：`type      | "text/preview"   | chars | refs`

```
type      | "text/preview"   | chars | refs
body      | "ICS 59.080.30\nW63"                                  | 17   | 1,1,index
title[00] | "中华人民共和国纺织行业标准"                            | 12   | 1,2,title
body      | "FZ/T 73020—2019\n代替FZ/T73020—2012…"               | 80   | 1,3,paragraph; 1,4,paragraph; 1,5,paragraph; 1,6,paragraph; 1,7,paragraph; 1,8,paragraph
title[01] | "中华人民共和国纺织"                                    | 9    | 2,1,title
title[02] | "行业标准"                                              | 4    | 2,2,title
body      | "针织休闲服装…"                                        | 280  | 2,3,paragraph; 2,4,paragraph
title[03] | "前 言"                                                 | 3    | 3,1,title
body      | "本标准按照GB/T 1.1—2009…本标准代替 FZ/T"             | 1456 | 3,2,paragraph; 3,3,paragraph
```

连续 title[01] + title[02] 之间无 body 行——title[01] 无正文，视觉上即可读出。

**为什么 title 有 `[NN]` 而 body 没有**：

| 设计点 | 原因 |
|-------|------|
| title 必须编号 | LLM 输出 `seq_ids: [1, 2]`，必须有直接映射桥梁；缺失则 LLM 须自己数行，易出错 |
| body 不编号 | body 永远不出现在 `seq_ids` 中；其作用是提供字数/预览上下文；位置已隐含归属 |
| 不对称是刻意设计 | 明确传达"只有 title 是分组单元，body 是附属信息"，防止 LLM 误将 body 放入 `seq_ids` |

### 3.2.1 `_format_refs` — block_refs 格式化

```python
def _format_refs(refs: list[list]) -> str:
    """将 block_refs 转为 'page,block,type; ...' 格式。

    - 每个三元组：page,block,type（逗号分隔，无括号）
    - 多个三元组：分号+空格分隔
    - 解析：split('; ') → 再 split(',') 三列
    """
    return "; ".join(
        f"{r[0]},{r[1]},{r[2]}"
        for r in refs
        if isinstance(r, list) and len(r) >= 3
    )
```

**两层分隔符不歧义**：`,` 分隔三元组内部字段，`; ` 分隔多个三元组。可直接 `split('; ')` 再 `split(',')` 解析校验。

### 3.3 三层校验（`_validate_and_fix`）

不变，seq_ids 仍为 0-based 整数（现在是 title 枚举位置）：

- **Layer 1 存在性**：所有 seq_id ∈ [0, max_seq_id]
- **Layer 2 连续性**：每组 seq_ids 内部连续，非连续则拆分
- **Layer 3 覆盖性**：遗漏 seq_id → 各自独立成节（无级联追加 bug）

### 3.4 EnhanceUnit 构建（`build_enhance_units`）

block_refs 组装（title → body，均为三元列表，直接 extend 无需 `.to_dict()`）：

```python
for idx in seq_ids:
    t = title_items[idx]          # 按位置索引，无需 title_map dict
    block_refs.append(t.block_ref)         # 三元列表，直接追加
    body = body_map.get(idx)
    if body:
        block_refs.extend(body.block_refs)  # 三元列表 list，直接 extend
```

### 3.5 page_range 计算

```python
def _compute_page_range(block_refs: list[list]) -> list[int]:
    pages = [r[0] for r in block_refs if isinstance(r, list) and len(r) >= 1]
    return [min(pages), max(pages)] if pages else [-1, -1]
```

page_no 取 `ref[0]`（1-based）。

## 4. EnhanceUnit 数据结构（`schema.py`）

```python
@dataclass
class EnhanceUnit:
    section_id: str          # "s001", "s002", …
    title: str               # LLM 给出或继承的单元标题
    seq_ids: list[int]       # 覆盖的 TitleItem 枚举位置列表（连续，0-based）
    body_text: str           # 拼接的正文文本（供增强 LLM 使用）
    block_refs: list[list]   # 三元列表有序 union：[page_no_1based, block_no_1based, type_str]
    page_range: list[int]    # [min_page_no, max_page_no]（1-based）
    estimated_tokens: int = 0
```

`block_refs` 格式变更：旧版 `list[dict]`（`{"page_idx":0, "block_idx":0, "type":"title"}`） → 新版 `list[list]`（`[1, 1, "title"]`）。

## 5. 整体流程

```
content_list_v2
    ↓
Stage 1: BlockIndexer
    → list[TitleItem | BodyItem]（flat，无树，无冗余 id 字段）
    ↓
_parse_items()
    → title_items, body_map, preamble
    ↓
Stage 3: SectionPlanStage
    LLM flat table → 3-layer validation → build_enhance_units
    → list[EnhanceUnit]
    ↓
Stage 4: TokenEstimationStage → Stage 5: SectionEnhanceStage
    → section_results（refs 字段为 [[page_no, block_no, type], ...]）
    ↓
Stage 6: DocEnhanceStage → Stage 7: ValidateStage → Stage 8: ComposeStage
```

## 6. 与旧方案对比

| 维度 | 旧方案 | 新方案 |
|------|--------|--------|
| 数据结构 | `BlockRef` dataclass + `TitleItem.seq_id` + `BodyItem.after_seq_id` | 三元列表 + 纯位置关联 |
| 空节点 | 连续 title 间有空 BodyItem | 空 BodyItem 不发射 |
| block_refs 格式 | `{"page_idx": 0, "block_idx": 0, "type": "title"}` | `[1, 1, "title"]`（1-based） |
| page_range | 0-based page_idx | 1-based page_no |
| SectionNode 树 | 必须 | 不存在，全程 flat list |
| seq_id | 存储在 TitleItem 字段 | 由 `enumerate` 动态给出 |
| 消费侧关联 | `body_map = {x.after_seq_id: x ...}` | `_parse_items()` 按位置推导 |
