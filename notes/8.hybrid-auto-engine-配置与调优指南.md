# MinerU Hybrid-Auto-Engine 配置与调优指南

> 目标：归纳 `hybrid-auto-engine` 的核心分流逻辑、VLM 引擎自动选择机制，以及 M1 Max / Win11(1660Ti 6G) 的可执行优化模板。

---

## 1. 为什么 `hybrid-auto-engine` 要按 `_vlm_ocr_enable` 分流

`hybrid` 的核心不是“固定一条链路跑到底”，而是根据文档与参数条件，在两条路径之间做平衡：

- 路径A（`_vlm_ocr_enable=True`）：VLM OCR 增强路径  
  - 仅执行 VLM 两阶段提取（版面+内容）。  
  - 目标：在满足条件时，获得更强语义一致性和更简化的后处理链路。

- 路径B（`_vlm_ocr_enable=False`）：VLM + 本地 OCR/公式补全路径  
  - 先 VLM 做版面，再补 OCR det/rec、行内公式识别。  
  - 目标：提升多语言/复杂场景的稳定性与兜底能力。

### 1.1 分流的真实用意

- **精度**：部分 OCR 场景 VLM 端到端更强（尤其中英文清晰文档）。
- **鲁棒性**：不满足 VLM OCR 条件时，仍可通过本地链路稳定产出。
- **可控性**：保留传统 OCR/公式链路的调参能力（批大小、阈值等）。

一句话：`hybrid` 通过动态分流，把“高上限”和“高稳定”同时保住。

---

## 2. `_vlm_ocr_enable` 的判定规则

默认逻辑（简化）：

```text
_vlm_ocr_enable =
  ocr_enable
  AND language in [ch, en]
  AND inline_formula_enable
  AND NOT MINERU_HYBRID_FORCE_PIPELINE_ENABLE
```

额外强制开关：

- `MINERU_FORCE_VLM_OCR_ENABLE=1`：强制开启 VLM OCR 增强路径
- `MINERU_HYBRID_FORCE_PIPELINE_ENABLE=1`：强制关闭 VLM OCR 增强路径，走本地补全链路

---

## 3. `auto-engine` 如何选择具体引擎

`hybrid-auto-engine` / `vlm-auto-engine` 在内部会走 `get_vlm_engine(inference_engine='auto', ...)`：

- Windows：优先 `lmdeploy`，否则 `transformers`
- Linux：优先 `vllm`（异步时 `vllm-async`），其次 `lmdeploy`，最后 `transformers`
- macOS（Apple Silicon）：优先 `mlx`，否则 `transformers`

也就是说：

- M1/M2/M3 场景通常目标是 `mlx-engine`
- Win11 通常优先 `lmdeploy-engine`

可从日志确认最终选择，典型日志形态：

```text
Using xxx-engine as the inference engine for VLM.
```

## 4. “可选的 VLM 增强”具体作用

### 4.1 VLM OCR 增强开关（最关键）

- 作用：决定走路径A还是路径B。
- 影响：文本提取主导是“VLM端到端”还是“VLM+本地补全”。

### 4.2 表格增强（`-t` / `MINERU_VLM_TABLE_ENABLE`）

- 作用：控制表格相关链路（含后处理能力，如跨页表格合并）。
- 影响：表格结构质量、跨页连贯性、耗时。

### 4.3 公式增强（`-f` + Hybrid 特殊行为）

- 在 `hybrid-*` 分支中，`MINERU_VLM_FORMULA_ENABLE` 在代码中为固定开启（true）。
- 但 `-f` 仍影响 `inline_formula_enable` 及 `_vlm_ocr_enable` 判定条件。
- 影响：行内公式补全与路径分流行为。

### 4.4 标题层级 LLM 辅助（配置项）

- 作用：文档后处理中优化标题层级。
- 影响：结构化可读性提升，但会增加额外耗时与依赖。

## 5. M1 Max 64G：安装 `mlx_vlm` 与使用建议

## 5.1 安装（推荐）

```bash
# 在虚拟环境中执行
uv pip install -U "mineru[mlx]"
```

或源码模式：

```bash
uv pip install -e ".[mlx]"
```

验证：

```bash
python -c "from mlx_vlm import load; print('mlx_vlm ok')"
```

## 5.2 如何使用 `mlx-engine`

无需在 `-b` 里显式写 `mlx-engine`。  
继续用 `hybrid-auto-engine` / `vlm-auto-engine` 即可，`auto` 会在 macOS 上优先选择 `mlx-engine`（依赖满足时）。

---

## 6. Win11 + 32G 内存 + 1660Ti 6G：选型建议

该设备瓶颈主要在 6G 显存，建议优先级：

1. **最稳**：`pipeline`
2. **效果与稳定平衡**：`hybrid-http-client`（远端跑 VLM，本地做小模型补全）
3. **本地强跑**：`hybrid-auto-engine`（可能慢、可能显存紧张）

结论：若有远端 OpenAI 兼容 VLM 服务，优先 `hybrid-http-client`。

## 7. 双设备三档模板（可直接复制）

> 说明：以下模板按“稳妥 / 均衡 / 性能”分档。  
> 如果遇到 OOM，先降 `MINERU_PROCESSING_WINDOW_SIZE`，再降 `MINERU_HYBRID_BATCH_RATIO`。

### 7.1 M1 Max 64G

#### 稳妥档（优先稳定）

```bash
export MINERU_PROCESSING_WINDOW_SIZE=16
export MINERU_HYBRID_BATCH_RATIO=2
export MINERU_API_MAX_CONCURRENT_REQUESTS=1

mineru -p <input.pdf> -o <out_dir> \
  -b hybrid-auto-engine -m auto -l ch -f true -t true
```

#### 均衡档（推荐日常）

```bash
export MINERU_PROCESSING_WINDOW_SIZE=24
export MINERU_HYBRID_BATCH_RATIO=4
export MINERU_API_MAX_CONCURRENT_REQUESTS=1

mineru -p <input.pdf> -o <out_dir> \
  -b hybrid-auto-engine -m auto -l ch -f true -t true
```

#### 性能档（吞吐优先）

```bash
export MINERU_PROCESSING_WINDOW_SIZE=32
export MINERU_HYBRID_BATCH_RATIO=4
export MINERU_FORCE_VLM_OCR_ENABLE=1
export MINERU_API_MAX_CONCURRENT_REQUESTS=1

mineru -p <input.pdf> -o <out_dir> \
  -b hybrid-auto-engine -m ocr -l ch -f true -t true
```

### 7.2 Win11 + 1660Ti 6G

#### 稳妥档（最不容易失败）

```bat
set MINERU_PROCESSING_WINDOW_SIZE=8
set MINERU_API_MAX_CONCURRENT_REQUESTS=1

mineru -p <input.pdf> -o <out_dir> ^
  -b pipeline -m auto -l ch -f true -t true
```

#### 均衡档（推荐：远端 VLM）

```bat
set MINERU_PROCESSING_WINDOW_SIZE=8
set MINERU_HYBRID_BATCH_RATIO=1
set MINERU_API_MAX_CONCURRENT_REQUESTS=1

mineru -p <input.pdf> -o <out_dir> ^
  -b hybrid-http-client -u http://<your-vlm-server>:30000 ^
  -m auto -l ch -f true -t true
```

#### 性能档（本地强跑，风险较高）

```bat
set MINERU_PROCESSING_WINDOW_SIZE=4
set MINERU_HYBRID_BATCH_RATIO=1
set MINERU_API_MAX_CONCURRENT_REQUESTS=1
set MINERU_HYBRID_FORCE_PIPELINE_ENABLE=1

mineru -p <input.pdf> -o <out_dir> ^
  -b hybrid-auto-engine -m auto -l ch -f false -t false
```

## 8. 快速排障检查单

1. **确认引擎是否符合预期**  
   - 查日志：`Using xxx-engine as the inference engine for VLM.`

2. **确认是否进入 VLM OCR 增强路径**  
   - 看中间结果标记或日志中的 `_vlm_ocr_enable` 分流行为。

3. **OOM/卡顿优先调整顺序**  
   - 第一步：降低 `MINERU_PROCESSING_WINDOW_SIZE`
   - 第二步：降低 `MINERU_HYBRID_BATCH_RATIO`
   - 第三步：Win11 6G 改用 `hybrid-http-client` 或 `pipeline`

4. **Mac 未选到 MLX**  
   - 检查 `mlx_vlm` 是否安装成功，且运行环境是否为 Apple Silicon + 支持版本 macOS。

---

## 9. 总结

- `hybrid-auto-engine` 的价值在于“动态分流”，不是单链路执行。
- `auto-engine` 会按平台能力选引擎；M1 目标是 `mlx-engine`，Win11 目标通常是 `lmdeploy-engine`（或退回 `transformers`）。
- 对资源紧张设备（如 1660Ti 6G），优先把 VLM 推理外移到 `hybrid-http-client`。
