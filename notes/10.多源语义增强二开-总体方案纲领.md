## 1. 终极目标

在 `MinerU` 现有解析链路（`pipeline` / `hybrid-auto-engine`）后，增加一条**可配置、可追溯、可降级**的语义增强后处理链，实现：

1. 图像/表格多模态语义增强（结合上下文）
2. 文档级摘要（NotebookLM 风格）+ 章节/段落级摘要、关键词、QA
3. 将增强内容按规则插回 Markdown
4. 同步输出结构化增强产物，便于后续检索、审计、回放

---

## 2. 与 MinerU 工作流的对齐（✅ 已确认）

### 2.1 关键挂载点

`mineru/cli/common.py` → `_process_output(...)` 为统一增强入口。

- 已统一接收 `pdf_info`、`middle_json`、`model_output`
- 已完成 `make_func(...)` 的内容生成分派
- 已包含 md/json 写出逻辑，适合在写 md 前后注入增强流程

### 2.2 pipeline / hybrid 兼容性

- `pipeline`：`make_func = pipeline_union_make`
- `hybrid/vlm`：`make_func = vlm_union_make`
- 两条后端最终都收敛到 `pdf_info + middle_json`

**原则**：增强模块不绑定后端细节，绑定统一中间结构（`middle_json` / `content_list_v2`）。

## 3. 核心架构思想

采用 Hermes 风格的四段式执行思想：

1. **Planner**：任务规划（识别章节、图片、表格、全局摘要任务）
2. **Worker**：并行执行（图像/表格多模态 + 章节摘要 + 文档摘要）
3. **Judge**：质量门控（证据检查、冲突检查、阈值过滤）
4. **Composer**：插回 markdown + 输出增强 JSON

满足三点：并行效率、质量可控、结果可追溯。

> **Phase 1 实际落地**：四段式思想已演化为 8 阶段 pipeline（Input → SectionBuild → **SectionPlan** → TokenEstimation → SectionEnhance → DocEnhance → Validate → Compose），详见 `notes/14`、`notes/19`（SectionPlanStage）。

## 5. 能力版图（三阶段路线图）

### 5.1 Phase 1 — 文本语义增强（✅ 已完成）

**章节级增强**（每个 section 输出）：

| 字段 | 说明 | 消费方 |
|------|------|--------|
| `summary` | 检索向自包含摘要 | 节级向量、Doc 级汇总输入 |
| `keywords` | 实体 + 任务词 + 同义词（6~10 个） | BM25/标签/扩展查询 |
| `main_idea` | 单句核心论点 | 粗路由、列表展示 |

**文档级增强**（`overview` 输出）：

| 字段 | 说明 | 消费方 |
|------|------|--------|
| `global_summary` | 叙述式全文摘要（问题—方法—结果—边界） | 文档级向量、产品摘要 |
| `global_keywords` | 文档级关键词（≥8 个） | 文档级标签、过滤 |
| `doc_outline_insights` | 命题级洞察列表，每条含 `{text, section_id}` | 多路召回、主题路由 |

**已落地的技术规格**：
- 层级化 section tree 构建 → `notes/13`
- 三模式自适应调度（A/B/C）+ 输出格式 → `notes/14`
- 字段语义契约与质量门禁 → `notes/15`
- Prompt 质量优化 → `notes/16`
- LLM 驱动的自适应 Section 规划 → `notes/19`

**产物**：
- `{name}_enhance.json`（结构化增强结果）
- `{name}.md`（增强版 Markdown，唯一 md）

### 5.2 Phase 2 — 多模态增强 + 质量护栏（⏳ 待实施）

**图像/表格多模态增强**：

每个 image/table task 输入：
- `page_idx`, `bbox`, `block_id`
- `image_path` 或 `table_html`
- 上下文窗口（前后文本）
- 标题、caption、footnote

每个 image/table task 输出：
- `semantic_label`
- `role_in_doc`（证据/流程/对比/示例）
- `key_facts`
- `related_keywords`
- `evidence_refs`
- `confidence`

表格增强优先级：
1. 有 `html`：结构化解析优先
2. 无 `html`：VLM 图像理解
3. 大表：分块总结再合并

**章节级扩展字段**（在现有 summary/keywords/main_idea 基础上新增）：
- `function_in_doc`（章节在文档中的角色）
- `qa_pairs`（章节级问答对）
- `evidence_refs`（证据引用）
- `confidence`（增强结果置信度）

**文档级扩展字段**（在现有 global_summary/global_keywords/doc_outline_insights 基础上新增）：
- `core_themes`（核心主题）
- `doc_faq`（全局 FAQ/QA）
- `evidence_refs`（文档级证据引用）

**Grounded 约束**：
所有增强必须具备 `evidence_refs`，否则不插正文、仅写入报告或直接丢弃。该机制是防幻觉、防误导的核心护栏。

**其他 Phase 2 能力**：
- Judge 质量门控完善（`confidence` 阈值 + `evidence_refs` 强制校验）
- 缓存与预算控制（缓存键：`doc_hash + block_id + prompt_version + model`）
- 子能力开关（IMAGE/TABLE/SECTION/DOC_SUMMARY 独立控制）
- 增强模式分档（off/light/standard/deep）

**产物扩展**（在 Phase 1 基础上新增）：
- `{name}.enhanced.md`（与原始 md 分离的增强版）
- `{name}_enhancement_report.json`（执行报告：任务数量/成功率/过滤原因/token 统计/模型快照）

## 8. 风险与防护

### 8.1 主要风险

- 增强内容与原文冲突
- 图片/表格脱离上下文造成误判
- 大文档成本和时延不可控
- 模型不稳定导致结构化输出失败

### 8.2 防护策略

| 策略 | 状态 |
|------|------|
| JSON schema 校验（失败即降级） | ✅ Phase 1 已实现（ValidateStage） |
| 降级顺序：多模态失败 → 文本增强 → 仅原文输出 | ✅ Phase 1 已实现（status=failed 不中断） |
| section/doc 退化检测 + retry | ✅ Phase 1 已实现（标题退化/summary 退化/同质化检测） |
| 强制 `evidence_refs` 校验 | ⏳ Phase 2 |
| `confidence` 阈值门控 | ⏳ Phase 2 |
| 缓存键 `doc_hash + block_id + prompt_version + model` | ⏳ Phase 2 |
