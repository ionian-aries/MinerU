## 0. 重构动机与核心问题

### 0.1 旧方案的根本缺陷

| 问题 | 现象 | 根因 |
|------|------|------|
| SectionBuildStage 层级推断不稳定 | raw_level 全为 1/2，heuristic 虽能推断但有误判边界 | 过度依赖规则，文档多样性无法穷举 |
| SectionPlanStage 只能合并同父连续兄弟 | 跨父边界的小节无法聚合 | 树结构约束 + LLM 输入是树形 outline |
| Bottom-up 增强内容膨胀 | 16字 L4 节增强后汇总到 L2，enhanced > original | 对粒度不合理的节点反复增强 |
| enhance_depth 影响不可控 | depth=2 时小文档汇总层数不合适 | 静态配置无法适应动态文档结构 |
| Section summary 语义密度不足 | "本节介绍了…检验方法" 无具体技术内容 | Prompt 未要求技术密集型输出 |
| 文档路由能力弱 | 无法快速判断某文档是否能回答某类问题 | 缺少"可回答问题"的显式表示 |

### 0.2 重构目标

1. **通用性**：不依赖 heuristic 层级推断，适配任意文档类型
2. **Refs 合法性**：block_refs 完全由物理扫描顺序决定，100% 合法有效
3. **增强粒度合理**：LLM 决定分组粒度，消除 bottom-up 膨胀
4. **RAG 召回率提升**：section 级 `questions` + doc 级 `answerable_questions`，从查询方向匹配

## 1. content_list_v2 生成机制（约束基础）

### 1.1 调用链

```
common.py::_process_output()
    └─ make_func(pdf_info, MakeMode.CONTENT_LIST_V2, image_dir)
           └─ pipeline/vlm/office 各后端 union_make(pdf_info_dict, mode)
                  └─ 按页遍历 pdf_info_dict：
                     para_blocks = merge_adjacent_ref_text_blocks_for_content(
                         (paras_of_layout or []) + (paras_of_discarded or [])  ← 两者都合并！
                     )
                     for para_block in para_blocks:
                         para_content = make_blocks_to_content_list_v2(...)
```

### 1.2 关键约束

- `page_idx` = 外层数组的 `enumerate` 索引，**不存储在 block 内**

- **`discarded_blocks` 与 `para_blocks` 均被合并进 content_list_v2**，`discard.types` 配置的块依然出现在 content_list_v2 中

## 2. Block Indexer（替换 SectionBuildStage）

### 2.1 设计决策

**采用两种独立结构**，不使用统一 RawSegment（**已实施，字段已简化，见下**）：

```python
@dataclass
class TitleItem:
    title_text: str      # 原始标题文本（不含任何 level 信息）
    block_ref: list      # [page_no_1based, block_no_1based, "title"]  ← 1-based 三元列表

@dataclass
class BodyItem:
    char_count: int = 0            # 可读文本字符数（不含 image/table）
    preview: str = ""              # 智能截取预览（首尾对称采样，见 2.4）
    block_refs: list[list] = ...   # [[page_no, block_no, type], ...]  ← 1-based 三元列表
    body_text: str = ""            # 完整文本（供后续 LLM 使用）
```

> **与原始设计的差异**：
> - 原始设计有 `TitleItem.seq_id` 和 `BodyItem.after_seq_id` 字段 → **已移除**
> - 原始设计有 `BlockRef` dataclass → **已移除，改用纯列表 `[page, block, type]`**
> - block_refs 编码从 0-based `page_idx/block_idx` → **改为 1-based `page_no/block_no`**
> - 位置关联完全由数组顺序表达，无需存储在字段中

**为什么两种结构而非统一结构**：
- 字段含义无歧义，无需 `is_preamble` 等 flag
- TitleItem 和 BodyItem 各自语义清晰，扩展时互不污染
- 映射文档物理结构：文档就是 title 与 body 交替出现

### 2.2 Skip 策略（动态构建，感知 discard 配置）

```python
_ALWAYS_SKIP_V2 = frozenset({
    "page_header", "page_footer", "page_number",
    "page_aside_text", "page_footnote",
})

_BLOCK_TYPE_TO_CONTENT_TYPE_V2: dict[str, set[str]] = {
    "header":               {"page_header"},
    "footer":               {"page_footer"},
    "page_number":          {"page_number"},
    "aside_text":           {"page_aside_text"},
    "page_footnote":        {"page_footnote"},
    "image":                {"image"},
    "table":                {"simple_table", "complex_table"},
    "chart":                {"chart"},
    "interline_equation":   {"equation_interline"},
    "seal":                 {"seal"},
    "code":                 {"code", "algorithm"},
    "list":                 {"list"},
    "index":                {"index"},
    "ref_text":             {"list"},
    "text":                 {"paragraph"},
    "abstract":             {"paragraph"},
    "title":                {"title"},
}

def build_skip_set(custom_config: CustomConfig) -> frozenset[str]:
    """动态构建 skip set，合并内置跳过类型 + custom_config.discard.types 映射。"""
    skip = set(_ALWAYS_SKIP_V2)
    custom_types = (custom_config.discard or {}).get("types") or []
    for block_type in custom_types:
        skip.update(_BLOCK_TYPE_TO_CONTENT_TYPE_V2.get(block_type, set()))
    return frozenset(skip)
```

**规则**：
- 在 skip_set 中的 block → 完全丢弃，**不进 block_refs，不进文本**
- 不在 skip_set 的文本类（title/paragraph/list/index）→ 进 block_refs **且** 进文本
- 不在 skip_set 的视觉类（image/table/chart/equation/seal/code）→ 进 block_refs，**不进文本**（caption 文本可选加入，用 `[图/表注: ...]` 标记）

### 2.3 扫描算法（伪代码）

```
seq_counter = 0
current_body: BodyItem | None = None
items: list[TitleItem | BodyItem] = []
skip_types = build_skip_set(custom_config)

for page_idx, page_blocks in enumerate(content_list_v2):
    for block_idx, block in enumerate(page_blocks):
        block_type = block["type"]

        # ① 丢弃类：完全跳过
        if block_type in skip_types:
            continue

        block_ref = {"page_idx": page_idx, "block_idx": block_idx, "type": block_type}

        # ② Title block → 触发新 TitleItem
        if block_type == "title":
            if current_body is not None:
                items.append(finalize_preview(current_body))
                current_body = None

            title_text = extract_title_text(block)
            items.append(TitleItem(seq_id=seq_counter, title_text=title_text, block_ref=block_ref))
            seq_counter += 1

            current_body = BodyItem(after_seq_id=seq_counter - 1, block_refs=[], body_text="", char_count=0)

        # ③ 文本类 → 进 refs + 进文本
        elif block_type in {"paragraph", "list", "index"}:
            if current_body is None:
                current_body = BodyItem(after_seq_id=-1, block_refs=[], body_text="", char_count=0)
            current_body.block_refs.append(block_ref)
            text = extract_text_recursive(block)   # list/index 需递归 list_items
            current_body.body_text += text + "\n"
            current_body.char_count += len(text)

        # ④ 视觉类 → 仅进 refs
        else:
            if current_body is None:
                current_body = BodyItem(after_seq_id=-1, block_refs=[], body_text="", char_count=0)
            current_body.block_refs.append(block_ref)
            caption = extract_caption_text(block)   # 可选：image_caption / table_caption
            if caption:
                current_body.body_text += f"[图/表注: {caption}]\n"

# 封装最后一个 body
if current_body is not None:
    items.append(finalize_preview(current_body))
```

### 2.4 Preview 截取策略（已实施版本）

```python
def _finalize_body(body: BodyItem) -> BodyItem:
    text = body.body_text.strip()
    if not text:
        body.preview = ""
    elif len(text) <= 50:
        body.preview = text                              # 全文
    elif len(text) <= 200:
        body.preview = text[:50] + "…" + text[-50:]    # 首 50 + 尾 50
    else:
        body.preview = text[:80] + "…" + text[-80:]    # 首 80 + 尾 80
    return body
```

> **与原始设计的差异**：原始设计为 `≤200 → text[:80]+"…"`（无尾部）、`>200 → text[:60]+"…"+text[-30:]`（不对称）。
> 已修正为**对称首尾采样**，阈值和长度均调整为更合理的值。

### 2.5 Preamble 处理

首个 title 前的所有 block 构成一个普通 `BodyItem`（`_parse_items()` 提取为 `preamble` 变量）。在 LLM flat_table 中以无序号的 `body` 行展示（首行），LLM 自主决定是否将其合并入相邻 section。

> **与原始设计的差异**：原始设计用 `BodyItem(after_seq_id=-1)` 标记 preamble。已简化：`BodyItem` 无 `after_seq_id` 字段，preamble 由 `_parse_items()` 通过位置推断提取。

### 2.6 list/index 文本递归提取

```
extract_text_recursive(block):
    if block.type in {paragraph}: return spans 拼接
    if block.type in {list, index}:
        for item in content.list_items:
            for span in item.item_content:
                累积 span.content（处理 text/equation_inline 等类型）
    return 拼接结果
```

## 3. LLM Section Planner（替换 SectionPlanStage）

### 3.1 定位

不再使用树结构，完全 flat 的 LLM 语义规划：
- 输入：`TitleItem[]` + 配对的 `BodyItem[]`
- 输出：分组计划（哪些连续 seq_ids 构成一个 section）
- 约束：**必须连续，不允许跳跃**

### 3.2 LLM 输入构建（已实施版本）

**实施后采用四列表格格式**，完整定义见 notes/19 § 3.2 和 § 3.2.1。

```
type      | "text/preview"   | chars | refs
body      | "ICS 59.080.30\nW63"          | 17   | 1,1,index
title[00] | "中华人民共和国纺织行业标准"    | 12   | 1,2,title
body      | "FZ/T 73020—2019 代替FZ/T…"  | 80   | 1,3,paragraph; 1,4,paragraph; ...
title[01] | "中华人民共和国纺织"            | 9    | 2,1,title
title[02] | "行业标准"                      | 4    | 2,2,title
body      | "针织休闲服装…"               | 280  | 2,3,paragraph; ...
```

**列规则**：
- `title[NN]`：NN 直接对应 `seq_ids` 整数，两位补零
- `body`：无序号，位置隐含归属前一 title
- `chars`：title = `len(title_text)`，body = `char_count`
- `refs`：`page,block,type; page,block,type`（逗号分隔三元组，分号分隔多个）

> **与原始设计的差异**：原始设计为 `seq=XX | "title" | chars=N | preview=...` 格式。
> 已重设计为四列结构：更清晰区分 title/body、统一 chars 列、refs 改为原始三元组格式。

**关键原则**（不变）：**不包含任何 level_hint**。level 信息来自 MinerU 模型，不可靠，加入 LLM prompt 会增大幻觉风险。LLM 从标题文字自行判断文档结构。

### 3.3 LLM Prompt 设计原则

```
System: 你是专业的文档结构分析专家。

User:
以下是文档《{doc_name}》按原文顺序排列的内容段落列表。
每行：段落编号(seq) | 标题文本 | 正文字数 | 正文预览

任务：请根据语义相关性和内容完整性，将相邻段落合并为合理的章节单元。

原则：
- 主题紧密关联的相邻段落应合并为一个单元
- 正文极少（如仅为章节编号跳转）的段落通常应与相邻段落合并
- 独立完整主题的段落应单独成节
- 以适合后续语义增强的粒度划分：单元应有足够内容支撑摘要和关键词提取
- 合并只能针对连续段落，禁止跳跃
- 不设字数最低/最高限制，以语义关联度为唯一标准

[段落列表]
{flat_table}
```

**无硬性约束**（不写最少字数、不写最终数量范围），完全语义驱动。

### 3.4 LLM 输出 Schema

```json
{
  "sections": [
    {
      "seq_ids": [0, 1, 2],
      "title": "文档信息与前言",
      "rationale": "前置内容、标准号、前言均为引言性内容，无独立增强价值"
    },
    {
      "seq_ids": [3, 4, 5, 6, 7],
      "title": "范围、规范性引用文件与术语定义",
      "rationale": "基础定义类内容，语义相近"
    }
  ]
}
```

### 3.5 三层校验（严格）

```
Layer 1 存在性：所有 seq_id ∈ [0, max_seq_id]
Layer 2 连续性：每个 section 内 seq_ids = list(range(min, max+1))（无跳跃无重复）
Layer 3 覆盖性：所有 sections 的 seq_ids 并集 = [0, max_seq_id] 全集（无遗漏无重叠）
```

**自动修复策略（已实施版本）**：
- 非法 seq_id → 过滤剔除
- 非连续 → 拆分为多个连续组（各组独立成节）
- 遗漏 → **每个遗漏 seq_id 各自独立成节**（`{"seq_ids": [sid], "title": "章节NN", "rationale": "自动补全"}`）
- 三次重试后仍失败 → fallback：每个 TitleItem 独立成节

> **与原始设计的差异**：原始设计遗漏处理为"追加到字数较少的相邻 section"，存在级联追加 bug（相邻 section 可能触发新的不连续）。已修正为**每个遗漏 seq_id 独立成节**，彻底消除级联问题。

### 3.6 section_id 分配与 block_refs 后置构建

```python
def build_enhance_units(validated_plan, title_items, body_map, preamble):
    units = []
    title_map = {t.seq_id: t for t in title_items}

    for i, section in enumerate(validated_plan.sections):
        section_id = f"s{i+1:03d}"   # 此时才分配 section_id
        block_refs = []

        # preamble 归入首个覆盖 seq_id=0 的 section
        if min(section.seq_ids) == 0 and preamble:
            block_refs.extend(preamble.block_refs)

        for seq_id in sorted(section.seq_ids):
            t = title_map[seq_id]
            block_refs.append(t.block_ref)           # title block
            body = body_map.get(seq_id)
            if body:
                block_refs.extend(body.block_refs)   # body blocks

        body_text = "\n".join(
            body_map[sid].body_text
            for sid in sorted(section.seq_ids)
            if sid in body_map
        )

        units.append(EnhanceUnit(
            section_id=section_id,
            title=section.title,
            seq_ids=section.seq_ids,
            body_text=body_text,
            block_refs=block_refs,    # 物理顺序，合法保证
            page_range=compute_page_range(block_refs),
        ))
    return units
```

**Refs 合法性保证**：
- seq_id 是物理扫描时分配的永久索引
- block_refs 是顺序 union，文档物理顺序决定
- section 覆盖连续 seq_ids → block_refs 天然物理连续
- 可能跨页（page_idx 不同），但 (page_idx, block_idx) 组合唯一且有效

## 4. SectionEnhanceStage 简化

### 4.1 废弃 Bottom-Up 增强

**废弃原因**（基于 RAG 最佳实践 + 研究）：

- RAPTOR 的效果来自对原文直接摘要，而非 summary-of-summaries
- LlamaIndex SummaryIndex 采用单层摘要，不递归
- Bottom-up 在叶节点内容极少时产生"enhanced > original"的膨胀问题
- 新方案中 LLM Section Planner 已在规划阶段保证每个单元有足量内容

**废弃的代码**：
- `enhance_depth` 参数
- `_collect_leaf()` 树遍历
- bottom-up parent 增强循环
- `_build_result_tree()` 嵌套输出
- `source_section_ids` / `merge_type` 字段

**保留并复用**：
- `_schedule_enhance_tasks()` 全量不变（Mode A/B/C + FFD 装箱 + 并发）
- `_execute_batch()` / `_enhance_single_via_prompt()` 全量不变
- `_refs_to_tuples()` 不变（1-based block_idx 输出约定不变）

新的 SectionEnhanceStage：**输入 EnhanceUnit[]（flat），对每个 unit 直接增强一次，输出 flat list[dict]（无 subsections 嵌套）**。

### 4.2 新增 `questions` 字段（HyDE 思想）

**背景**：Hypothetical Document Embedding（Gao et al. 2022）证明，在嵌入侧从文档方向生成"查询形式的表示"能显著提升稠密检索命中率。

每个 section 新增：

```json
{
  "summary": "技术密集型摘要 80-150字",
  "keywords": ["领域专属术语", "5-8个"],
  "main_idea": "核心命题 1句",
  "questions": [
    "这个 section 能直接回答的典型用户问题1",
    "典型用户问题2"
  ]
}
```

### 4.3 Summary 质量标准

**旧（叙述型，差）**：
> "本节介绍了甲醛含量的检验方法和要求。"

**新（技术密集型，好）**：
> "针织休闲服装甲醛含量按 GB/T 2912.1 水萃取法检验；A 类婴幼儿产品限值≤20 mg/kg，B 类≤75 mg/kg，C 类≤300 mg/kg。"

### 4.4 System Prompt 核心约束更新

```
summary 必须：
  - 包含本节所有技术参数名称、数值阈值、引用标准编号
  - 以具体技术内容开头，禁止"本节介绍了…""主要内容为…"等空泛句式
  - 80-150字，技术密集优先于篇幅
  - 自包含，禁止"本节""如前所述"等上下文依赖表述

keywords 必须：
  - 领域专有名词、标准编号、技术参数名称
  - 禁止"检验""方法""要求""内容"等文档通用词
  - 5-8个

questions 必须：
  - 模拟用户真实提问方式（不是标题复述）
  - 每个问题能被本节内容直接回答
  - 2-3个，覆盖本节核心内容不同角度
```

## 5. DocEnhanceStage 优化

### 5.1 新增 `answerable_questions` 字段

**用途**：文档路由。当用户提出问题时，先在文档级 `answerable_questions` 中匹配，快速定位相关文档，再进入 section 级检索。

**输出 Schema**：

```json
{
  "global_summary": "技术范围型摘要",
  "global_keywords": ["文档级分类标签词", "8-15个"],
  "doc_outline_insights": [
    {"text": "跨章节原子命题", "section_id": "s003"}
  ],
  "answerable_questions": [
    "这份文档能回答的典型用户问题1",
    "典型用户问题2",
    "5-10个"
  ]
}
```

### 5.2 `doc_outline_insights` vs `answerable_questions` 定位区分

| 字段 | 形式 | 用途 |
|------|------|------|
| `doc_outline_insights` | 命题陈述句 + section_id | 多跳推理锚点，结构性事实 |
| `answerable_questions` | 问句 | 文档路由，query-to-doc 匹配 |

**示例对比**（FZ/T 73020-2019）：

```
doc_outline_insights:
  {"text": "A类婴幼儿产品各有害物质限值最严，B/C类依次宽松，
            贯穿技术要求第5章和试验方法第6章", "section_id": "s003"}

answerable_questions:
  "针织休闲服装A类和B类产品的甲醛含量限值分别是多少？"
  "针织休闲服装的起球考核指标有什么变化？"
  "FZ/T 73020-2019对荧光色服装有什么特殊规定？"
```

### 5.3 global_summary 新范式

**旧（叙述型）**：
> "本标准详细规定了针织休闲服装的各类技术要求，为行业生产提供了依据。"

**新（技术范围型）**：
> "FZ/T 73020-2019 规定针织休闲服装（上衣/裤子/裙子等）的产品分类、18 项内在质量指标（有害物质/色牢度/起球/尺寸稳定性）和外观质量要求；全部试验方法引用 GB/T 系列；A 类婴幼儿产品执行最严格限值；代替 2012 版。"

### 5.4 global_keywords 与 section keywords 互补原则

```
section keywords：具体技术参数、标准编号（细粒度）
  例：["GB/T 2912甲醛", "pH值GB/T 7573", "起球等级", "A类婴幼儿"]

global_keywords：文档分类标签（粗粒度，互补不重复）
  例：["针织休闲服装", "FZ/T行业标准", "纺织品有害物质", "质量检验规则", "产品分类A/B/C"]
```

## 6. 知识库录入策略（向量库设计）

每个 section → **两条向量记录**（知识库最终消费形式）：

```
Record A（正文语义）:
  text_to_embed = title + "\n" + summary + "\n" + keywords.join(", ")
  用途：稠密检索（Dense Retrieval）
  metadata: section_id, doc_name, page_range, refs

Record B（查询语义）:
  text_to_embed = questions.join("\n")
  用途：查询侧直接匹配（Query-to-Question）
  metadata: section_id, doc_name（指向同一 section）
```

每个 doc → **两条向量记录**：

```
Record A（文档内容）:
  text_to_embed = doc_name + "\n" + global_summary + "\n" + global_keywords.join(", ")
  用途：文档内容匹配

Record B（文档路由）:
  text_to_embed = answerable_questions.join("\n")
  用途：用户问题 → 相关文档快速路由
```

**检索流程**：
```
用户 Query Q
  → Step 1: 文档路由
      对所有 doc Record B 做稠密检索，找相关文档
  → Step 2: Section 检索
      对候选文档的 section Record A + Record B 做混合检索（Dense + BM25）
  → Step 3: 生成
      取命中 section 的 block_refs → 从 layout 定位原始内容 → 生成回答
```

## 9. 关键设计决策汇总

| 决策点 | 最终结论 |
|--------|---------|
| Block Indexer 数据结构 | 两种独立类型（TitleItem + BodyItem），无 seq_id/after_seq_id/BlockRef |
| Level hint 是否传给 LLM | ❌ 绝对不传，level 信息不可靠，增加幻觉风险 |
| Preamble 处理 | 普通 BodyItem，由 `_parse_items()` 位置推断提取，flat_table 中为无序号 body 行 |
| image/table 是否进 block_refs | ✅ 进 refs，不进文本（Phase 1 如此；Phase 2 加 VLM 语义增强） |
| page_header/footer 是否进 block_refs | ❌ 完全丢弃 |
| 自定义 discard.types 处理 | build_skip_set() 动态映射 BlockType→ContentTypeV2 |
| block_refs 格式 | 1-based 三元列表 `[page_no, block_no, type]`（原始设计为 0-based dict） |
| section_id 分配时机 | LLM 规划通过三层校验后才分配 |
| LLM Section Planner 硬性约束 | ❌ 无最少字数、无数量限制，完全语义驱动 |
| flat_table 格式 | 四列：`type[NN]\|"text"\|chars\|refs`（原始设计为 `seq=XX\|title\|chars\|preview`） |
| Coverage repair | 遗漏 seq_id 各自独立成节（原始设计为追加相邻，有级联 bug） |
| Bottom-up 增强 | ❌ 废弃，改为 flat 单次增强 |
| enhance_depth 参数 | ❌ 废弃 |
| section summary 字数 | 80-150字，技术密集 |
| section keywords | 5-8个，领域专属，禁通用词 |
| section 新增字段 | `questions`（2-3个用户问题，HyDE 思想） |
| doc 新增字段 | `answerable_questions`（5-10个，文档路由用） |
| global_summary 风格 | 技术范围型（含适用范围/主要约束/产品类型） |
