## 1. `hybrid-auto-engine` 为什么要按 `_vlm_ocr_enable` 分流

`hybrid` 不是固定单链路，而是根据文档条件切换两条路径：

- 路径A：`_vlm_ocr_enable=True`  
  只跑 VLM 两阶段提取（版面+内容），减少本地 OCR 补链。
- 路径B：`_vlm_ocr_enable=False`  
  VLM 做版面主干，本地再补 OCR det/rec 与行内公式。

### 1.1 设计用意

- **高上限**：满足条件时，VLM OCR 路径通常语义一致性更好。
- **高稳定**：不满足条件时，传统 OCR/公式链路兜底，保证可用性。
- **可调优**：保留本地批量、阈值等调参空间，适配不同设备。

一句话：`hybrid` 通过“动态分流”同时兼顾精度、稳定和资源约束。

## 2. `_vlm_ocr_enable` 判定逻辑

默认逻辑（简化）：

```text
_vlm_ocr_enable =
  ocr_enable
  AND language in [ch, en]
  AND inline_formula_enable
  AND NOT MINERU_HYBRID_FORCE_PIPELINE_ENABLE
```

可强制控制：

- `MINERU_FORCE_VLM_OCR_ENABLE=1`：强制开启 VLM OCR 路径
- `MINERU_HYBRID_FORCE_PIPELINE_ENABLE=1`：强制关闭 VLM OCR 路径

---

## 3. `auto-engine` 如何选具体引擎

`get_vlm_engine(inference_engine='auto', ...)` 的平台逻辑：

- Windows：优先 `lmdeploy`，否则 `transformers`
- Linux：优先 `vllm`（异步时 `vllm-async`），其次 `lmdeploy`，最后 `transformers`
- macOS(Apple Silicon)：优先 `mlx`，否则 `transformers`

日志确认方式（关键）：

```text
Using xxx-engine as the inference engine for VLM.
```

## 4. 可选 VLM 增强项说明

### 4.1 VLM OCR 增强开关（核心）

- 作用：决定走路径A还是路径B。
- 影响：文本主导来自 VLM 端到端还是本地 OCR 补链。

### 4.2 表格增强（`-t` / `MINERU_VLM_TABLE_ENABLE`）

- 作用：控制表格相关链路与后处理（如跨页表格合并）。
- 影响：表格质量、连贯性、耗时。

### 4.3 公式增强（`-f` 与 hybrid 的特殊行为）

- `hybrid-*` 下，VLM 侧公式能力在代码中保持开启。
- `-f` 仍会影响 `inline_formula_enable`，并间接影响 `_vlm_ocr_enable` 判定与补链行为。

### 4.4 标题层级 LLM 辅助（配置项）

- 作用：在后处理阶段优化标题层级。
- 影响：结构更规整，但会增加额外耗时。

## 5. M1 Max 64G：安装与推荐

### 5.1 安装 `mlx_vlm`

```bash
uv pip install -U "mineru[mlx]"
```

或源码环境：

```bash
uv pip install -e ".[mlx]"
```

验证：

```bash
python -c "from mlx_vlm import load; print('mlx_vlm ok')"
```

### 5.2 使用 `mlx-engine`

继续使用 `hybrid-auto-engine` / `vlm-auto-engine` 即可，`auto` 会在 macOS 上优先选 `mlx-engine`（依赖满足时）。

## 6. Win11 + 32G + 1660Ti 6G：如何选择

建议优先级：

1. **最稳**：`pipeline`
2. **推荐平衡**：`hybrid-http-client`（远端跑 VLM，本地跑小模型）
3. **本地强跑**：`hybrid-auto-engine`（可能慢、可能显存紧张）

结论：该配置下优先把 VLM 推理外移到远端。

## 7. Win11 `hybrid-http-client` 完整部署（重点）

## 7.1 架构拆分

- **远端 Linux**：启动 OpenAI 兼容 VLM 服务（`mineru-openai-server`）
- **本地 Win11**：执行 `hybrid-http-client`，并运行小模型补链

## 7.2 远端需要跑什么 VLM

推荐：

- 服务：`mineru-openai-server`
- 引擎：`vllm`（优先）或 `lmdeploy`
- 模型：MinerU VLM 主模型（如 `opendatalab/MinerU2.5-2509-1.2B`）

关键点：远端只跑 VLM 服务，本地不需要本地 VLM 大模型推理。

## 7.3 远端 Linux 启动步骤

```bash
# 1) 安装（按引擎选一套）
pip install -U "mineru[vllm]"
# 或
# pip install -U "mineru[lmdeploy]"

# 2) 下载VLM模型
mineru-models-download -m vlm

# 3) 启动OpenAI兼容服务
mineru-openai-server --engine vllm --port 30000
# 可改为 --engine auto / --engine lmdeploy
```

## 7.4 本地 Win11 启动步骤

```bat
REM 1) 安装（客户端环境）
pip install -U "mineru[lmdeploy]"

REM 2) 下载本地小模型（hybrid补链会用）
mineru-models-download -m pipeline

REM 3) 建议参数（1660Ti 6G）
set MINERU_PROCESSING_WINDOW_SIZE=8
set MINERU_HYBRID_BATCH_RATIO=1
set MINERU_API_MAX_CONCURRENT_REQUESTS=1

REM 4) 调用
mineru -p C:\path\to\input.pdf -o C:\path\to\out ^
  -b hybrid-http-client ^
  -u http://<remote_ip>:30000 ^
  -m auto -l ch -f true -t true
```

可选：

- `MINERU_VL_MODEL_NAME`：远端多模型时指定模型
- `MINERU_VL_API_KEY`：远端服务鉴权

## 8. 双设备三档模板

## 8.1 M1 Max 64G

### 稳妥档

```bash
export MINERU_PROCESSING_WINDOW_SIZE=16
export MINERU_HYBRID_BATCH_RATIO=2
export MINERU_API_MAX_CONCURRENT_REQUESTS=1

mineru -p <input.pdf> -o <out_dir> \
  -b hybrid-auto-engine -m auto -l ch -f true -t true
```

### 均衡档（推荐）

```bash
export MINERU_PROCESSING_WINDOW_SIZE=24
export MINERU_HYBRID_BATCH_RATIO=4
export MINERU_API_MAX_CONCURRENT_REQUESTS=1

mineru -p <input.pdf> -o <out_dir> \
  -b hybrid-auto-engine -m auto -l ch -f true -t true
```

### 性能档

```bash
export MINERU_PROCESSING_WINDOW_SIZE=32
export MINERU_HYBRID_BATCH_RATIO=4
export MINERU_FORCE_VLM_OCR_ENABLE=1
export MINERU_API_MAX_CONCURRENT_REQUESTS=1

mineru -p <input.pdf> -o <out_dir> \
  -b hybrid-auto-engine -m ocr -l ch -f true -t true
```

## 8.2 Win11 + 1660Ti 6G

### 稳妥档

```bat
set MINERU_PROCESSING_WINDOW_SIZE=8
set MINERU_API_MAX_CONCURRENT_REQUESTS=1

mineru -p <input.pdf> -o <out_dir> ^
  -b pipeline -m auto -l ch -f true -t true
```

### 均衡档（推荐）

```bat
set MINERU_PROCESSING_WINDOW_SIZE=8
```

## 9. 可复制脚本（集中版）

### 9.1 Win11 客户端脚本模板

```bat
@echo off
setlocal
set "INPUT_PATH=C:\path\to\input.pdf"
set "OUTPUT_DIR=C:\path\to\output"
set "REMOTE_VLM_URL=http://127.0.0.1:30000"

set "MINERU_PROCESSING_WINDOW_SIZE=8"
set "MINERU_HYBRID_BATCH_RATIO=1"
set "MINERU_API_MAX_CONCURRENT_REQUESTS=1"

mineru -p "%INPUT_PATH%" -o "%OUTPUT_DIR%" ^
  -b hybrid-http-client -u "%REMOTE_VLM_URL%" ^
  -m auto -l ch -f true -t true
endlocal
```

### 9.2 远端 Linux 启动脚本模板

```bash
#!/usr/bin/env bash
set -euo pipefail

PORT="${PORT:-30000}"
ENGINE="${ENGINE:-vllm}"

mineru-openai-server --engine "${ENGINE}" --port "${PORT}"
```

## 10. 排障检查单

1. 看日志确认引擎：`Using xxx-engine as the inference engine for VLM.`
2. 确认远端 URL 可达：`curl http://<remote_ip>:30000`
3. OOM 时先降：
   - `MINERU_PROCESSING_WINDOW_SIZE`
   - 再降 `MINERU_HYBRID_BATCH_RATIO`
4. Win11 6G 若仍不稳，优先改为：
   - `hybrid-http-client`（推荐）
   - 或 `pipeline`（最稳）

---

## 11. 最终建议

- M1 Max：优先 `hybrid-auto-engine`，目标引擎 `mlx-engine`。
- Win11 1660Ti 6G：优先 `hybrid-http-client`，远端跑 `mineru-openai-server`（建议 `vllm`）。
