## 1. 文档目的

在 `notes/14` 的七阶段 Pipeline 与双产物（`enhance.json` / `enhanced.md`）不变的前提下，**单独冻结**「文档级 + 章节级」语义增强字段的**语义与质量门禁**，服务于：

- 多路召回、搜索扩展、路由与过滤  
- 可核验的章节级引用（`section_id`）  
- 离线评测与回归（固定文档集 + 固定 query）

**说明**：`notes/14` §7.2～§7.4 中曾以 `overview.summary` / `keywords` / `outline` 描述 doc 级字段；当前实现仅认 **`global_summary` / `global_keywords` / `doc_outline_insights`**（数组元素为 `{ text, section_id }`），不做旧键名或别名字段的兼容迁移。条数目标与列表密度对齐，见 **§3.2** 与 `stages_doc_enhance._target_insight_count`。本文档为 **契约真源**。

## 3. 字段语义表（冻结）

### 3.1 Section 级（`sections[]` 中 `status=success` 的节点）

| 字段 | 消费方 | 语义约束 | 建议形态 |
|------|--------|----------|----------|
| `id` | 引用、路由、与 doc 洞察对齐 | 全树唯一 | 与 SectionBuild 一致 |
| `refs` | 精确定位块 | 可回溯正文 | 非空（Validate 约束） |
| `summary` | 节级向量、Doc 级汇总输入 | **检索向**：可含方法/数据/结论要点，忌空洞套话 | 字数区间由 §5.2 与门禁调整 |
| `keywords` | BM25/标签/扩展查询 | **实体 + 任务词 + 同义词**，避免仅 2～3 个泛词 | 建议 ≥5（见 §4.2） |
| `main_idea` | 粗路由、列表展示 | 单句核心论点，与 `summary` 分工明确 | 一句 |

### 3.2 Doc 级（`overview`）

| 字段 | 消费方 | 语义约束 | 建议形态 |
|------|--------|----------|----------|
| `global_summary` | 文档级向量、产品摘要 | **叙述 + 信息密度**：问题—方法—结果—边界；忌口号化 | 字数下限见 §5.2 |
| `global_keywords` | 文档级标签、过滤、扩展 | 可与 section 关键词**部分重叠**（利于检索），忌与 `global_summary` 整段复制 | 建议 ≥8 |
| `doc_outline_insights` | 多路召回、主题路由、**可引用** | 每条为**命题级洞察**，必须带 `section_id`；**同一 section_id 可多条**（恢复旧版列表密度） | `{ "text": string, "section_id": string }[]` |

**与早期纯字符串列表的区别**：当前为对象数组且 **必须可追溯到章节 id**；条数由 `_target_insight_count(L1)` 与 prompt 约束，不足时 Doc 阶段 **补生成重试一次**。

## 4. 离线评测集（回归）

### 4.1 文档级 Query（每篇建议 8～12 条，维度示例）

1. **主题**：本文核心科学问题是什么？  
2. **方法**：用了什么数据/模型/实验设计？  
3. **结果**：主要定量结论是什么？  
4. **对比**：与哪些基线或前人工作比较？  
5. **限制**：作者承认的局限是什么？  
6. **应用**：对领域实践/管理的含义是什么？（按领域替换）  
7. **实体**：包含 2～3 个专业术语或地名的短 query。  
8. **否定**：文中是否讨论了 X？（X 取文中**未**讨论的主题，测幻觉）

**通过标准（人工或半自动）**：

- 用 `global_summary` + 若干 `doc_outline_insights` 条目拼成上下文回答上述问题时 **无事实冲突**。  
- 至少 **50%** 的问题能对应到某条 `doc_outline_insights[i]`，且 `section_id` 所指章节与答案一致。

### 4.2 引用抽检（每篇抽 5 条 insight）

- 随机抽取 `doc_outline_insights[i]`，对照 `sections` 中 `id == section_id` 的 `summary` 与 `refs` 覆盖正文。  
- **目标**：抽检正确率 ≥ **90%**（首版）；低于阈值则收紧 prompt 或校验策略。

### 4.3 Section 级抽检（每篇抽 3 节）

- `keywords` 是否覆盖该节专有概念；`summary` 是否可被独立用于检索而不依赖标题。

## 5. 门禁阈值表（建议初值）

| 门禁 ID | 检查对象 | 规则 | 失败策略（建议） |
|---------|----------|------|------------------|
| G-DOC-01 | `global_summary` | 非空且长度 ≥ **L1**（如 120 汉字，或按 token 计） | 整段 doc 重试 1 次 → 仍失败则降级占位 |
| G-DOC-02 | `global_keywords` | 数量 ≥ **N_k**（建议 8） | 同左或记录告警 |
| G-DOC-03 | `doc_outline_insights` | 每条含 `text` + `section_id`；`section_id` 属于当前 section 树 | 剔除非法项；若剩余 < **N_o** 则重试或告警 |
| G-DOC-04 | 标题退化 | 与章节标题过度重合（启发式） | **一次重试**（与现有策略一致） |
| G-SEC-01 | `keywords` | 数量 ≥ **N_sk**（建议 5） | section 标 failed 或仅告警（与线上一致） |
| G-SEC-02 | `refs` | 非空 | 与现逻辑一致 |

### 5.1 分段函数（与实现对齐）

- **N_o（洞察条数下限）**：与 `stages_doc_enhance._target_insight_count(成功 L1 节数 n)` 一致：若 `n≤0` 则为 0；若 `n≤4` 则为 `max(n×2, 4)`；否则为 `min(max(n, 12), 22)`。Doc 阶段若仍不足，会 **追加一次 density 重试**（日志含 `doc_outline_insights sparse`）。  
- **L1、N_k**：随评测集调参，变更时同步更新本文、`_target_insight_count` 与单测/日志说明。

## 6. Map-Reduce（Doc 分组合并）约定

与 `notes/14` Stage 5 一致，当触发分组时：

- **局部组输出**仍使用与全局一致的 `overview` schema，便于最后一跳合并。  
- **全局合并**时，禁止模型将洞察合并成极少条空话；宜在 prompt 中写明 **insight 条数下限** 或 **与输入章节数的比例**。  
- **引用**：局部阶段仅包含部分章节时，最后一跳应 **只引用输入中出现的 `section_id`**，避免幻觉 id；Validate 阶段应剔除树外 id。

## 7. 落地顺序（流程）

1. 将 **§3**（字段语义）与 **§5**（门禁）固化为团队一页纸契约。  
2. 选定 **3～5 篇**代表 PDF，建立 **§4** 固定题集。  
3. 每轮只改一个变量（prompt / 阈值 / 模型），跑同一套题集，记录 G-DOC / G-SEC 通过率。  
4. 实现变更后，同步更新本文档 **状态** 与 `notes/14` §7 的交叉引用，避免文档分叉。
