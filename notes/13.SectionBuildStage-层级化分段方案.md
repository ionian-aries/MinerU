## 1. 核心原则

### 1.1 职责边界（严格单一）

SectionBuildStage **只做一件事**：把 `content_list_v2` 的扁平 block 序列，转换为一棵层级化的 section tree。

**不做的事**：
- ❌ 不做 token 估算
- ❌ 不做字数阈值切分
- ❌ 不做 LLM 调用
- ❌ 不做增强/摘要/关键词
- ❌ 不处理 token 超限（那是 SectionEnhanceStage 的事）
- ❌ 不做"过短 section 合并"

**输入输出**：
- 输入：`content_list_v2: list[list[dict]]`（也兼容 `list[dict]` 简化结构）
- 输出：`SectionNode`（根节点，其 `children` 是完整的 N 层 section tree）

**与 `enhance_depth` 的关系**：
- SectionBuildStage 构建**完整 N 层树**，不截断
- `enhance_depth` 只影响 SectionEnhanceStage（控制增强到哪一层深度）
- 两者完全解耦

**与 SectionPlanStage 的关系**（notes/19）：
- SectionBuildStage 产出的原始 tree 传入 SectionPlanStage（Stage 2b）
- SectionPlanStage 对碎片化文档做 LLM 驱动的合并分组，产出 EnhanceUnit tree
- SectionBuildStage 不做"过短 section 合并"——那是 SectionPlanStage 的职责

## 2. 数据结构

### 2.1 SectionNode（定义在 `schema.py`）

```python
@dataclass
class SectionNode:
    section_id: str                      # "sec_001", "sec_002", ...
    title: str                           # 标题文本
    level: int                           # 层级（0=root, 1=顶层, 2=二级, ...）
    own_text: str                        # 仅当前节点直属的文本（不含子节点文本）
    page_range: list[int]                # [起始页, 结束页]，-1 表示未设置
    block_refs: list[dict]               # 关联的 block 引用
    children: list['SectionNode']        # 子节点列表
    estimated_tokens: int = 0            # TokenEstimationStage 填充
    subtree_tokens: int = 0              # TokenEstimationStage 填充
    # SectionPlanStage 增加字段（用于 EnhanceUnit 标识）
    source_section_ids: list[str] = []   # 被合并的原始 id 列表
    merge_type: str = "standalone"       # "standalone" | "merged"
    unit_title: str = ""                 # LLM 给出的合并单元标题（merged 时使用）
```

**关键设计——`own_text` vs "全部文本"**：

```
"2. Methods"
  own_text = ""  ← 标题和子标题之间没有段落文本
  children:
    "2.1. Characterisation"
      own_text = "Flow duration curves..."  ← 这个子标题下的段落
```

`own_text` **只存当前节点直属的段落文本**，不递归收集子节点的文本。

## 3. 处理流程（5 个步骤，严格按序）

### 步骤 1：扁平化遍历，收集所有有效 block

遍历 `content_list_v2` 的每一页每一个 block，跳过非文本 block，形成一个有序的 `FlatBlock` 序列。

**输入归一化**：
- `list[list[dict]]` — 标准格式，外层=page_idx
- `list[dict]` — 简化格式，按 `page_idx` 字段分组或视为单页
- 空列表 — 空文档兜底

**跳过规则**：
```
跳过的 block types:
  image, table, chart, seal, equation_interline, code, algorithm,
  page_header, page_footer, page_number, page_aside_text, page_footnote
```

**文本提取**（`_extract_any_text` 统一入口）：
- title block → 从 `content.title_content` 提取
- paragraph block → 从 `content.paragraph_content` 提取
- list/index block → 从 `content.list_items[].item_content` 提取
- 兼容简化结构 → 从 `block["text"]` 提取

**FlatBlock 结构**：
```python
@dataclass
class FlatBlock:
    page_idx: int
    block_idx: int
    block_type: str          # "title" | "paragraph" | "list" | ...
    text: str                # 提取的纯文本
    raw_level: int | None    # 仅 title block 有值，来自 content["level"]
    is_title: bool
    resolved_level: int = 1  # 步骤 2 填充
```

---

### 步骤 2：解析真实 level（heuristic 优先）

**核心策略**：编号 heuristic 推断优先，raw_level 完全不参与。

**为什么不用 raw_level**：
- pipeline 后端：DOC_TITLE=1, PARAGRAPH_TITLE=2，只有两级。"2. Methods"(L2) 和 "2.1. Characterisation"(L2) 都是 L2 → **错误**
- hybrid/vlm 后端：默认全部 level=1 → **无信息量**
- raw_level 在两种后端都不可靠，编号 heuristic 精度最高

**`resolve_levels` 策略**：

```python
def resolve_levels(flat_blocks: list[FlatBlock]) -> None:
    """
    策略:
    1. 编号 heuristic 能推断 → 直接用 inferred level
    2. heuristic 推断不出 →
       a) 文档中存在任何成功推断的编号标题 → 无编号标题默认 L1
          （学术/技术文档中 Abstract/References 等是顶级章节）
       b) 文档完全无编号标题（纯自然标题）→ 用 raw_level 兜底
          （虽不精确，但至少保留相对层级信息，避免全部扁平化）
    """
```

**编号 heuristic 规则（12 种模式，按优先级排序）**：

| 优先级 | 模式 | 正则 | 示例 | Level |
|--------|------|------|------|-------|
| P1 | 多级数字编号 | `^\d+(\.\d+)*\s*\.?\s` | `1.` `2.1.` `2.1.1` | 按段数(1-4) |
| P2 | 数字+顿号 | `^\d+、` | `1、` `2、` | 1 |
| P3 | 数字+右括号 | `^\d+\)\s` | `1)` `2)` | 2 |
| P4 | 罗马数字 | `^(I{1,3}\|IV\|V\|VI{0,3}\|...)\.\s` | `I.` `V.` `VII.` `XX.` | 1 |
| P5 | 大写字母+点 | `^[A-Z]\.\s` | `A.` `B.` | 2 |
| P6 | 小写字母+点/括号 | `^[a-z][.)]\s` | `a.` `a)` | 3 |
| P7 | 中文法定编号 | `^第.+[章部篇编节款条项]` | `第一章` `第二节` `第三条` | 1/2/3 |
| P8 | 中文大写数字+顿号 | `^[一二三...十百]+、` | `一、` `二、` | 1 |
| P9 | 全角括号+数字/中文 | `^[（(][一二...\\d]+[）)]` | `（一）` `（1）` | 2 |
| P10 | 半角括号+字母 | `^\([a-hj-z]\)` | `(a)` `(b)` | 3 |
| P11 | 英文结构词 | `Chapter\|Part\|Section\|Appendix\|Annex` | `Chapter 1` `Section 2.1` | 按语义 |
| P12 | §+数字 | `^§\s*\d+(\.\d+)*` | `§1` `§1.1` | 按段数 |

**设计原则**：
- 宁可不推断(None)也不误推断
- 只匹配行首编号，避免 "A novel approach" 误命中
- 罗马数字(P4)必须在大写字母(P5)之前（I/V 既是罗马数字也是单字母）

### 步骤 3：标题栈构建 tree

核心算法。用栈（stack）追踪当前层级路径，遇到标题就根据 level 做栈的 push/pop，遇到段落就把文本归入栈顶节点。

```python
核心伪码:
for fb in flat_blocks:
    if fb.is_title:
        flush_text_to_top()                    # 积累的文本归入当前栈顶
        while stack[-1].level >= fb.level:     # 弹出同级或更低级
            stack.pop()
        new_node = SectionNode(...)
        stack[-1].children.append(new_node)    # 挂到栈顶的 children
        stack.append(new_node)                 # 入栈
    else:
        text_buffer.append(fb.text)            # 段落文本积累
flush_text_to_top()                            # 处理末尾文本
```

**栈变化示例（demo1 关键序列）**：

```
初始: stack = [root(L0)]

→ title "2. Methods" (L1)
  pop: 无（root.level=0 < 1）
  挂到 root.children
  stack = [root(L0), "2.Methods"(L1)]

→ title "2.1. Characterisation" (L2)
  pop: "2.Methods".level(L1) >= 2? 否
  挂到 "2.Methods".children
  stack = [root(L0), "2.Methods"(L1), "2.1."(L2)]

→ paragraph "Flow duration curves..."
  text_buffer.append(...)

→ title "2.2. Zero flow" (L2)
  flush: 段落 → "2.1.".own_text
  pop: "2.1."(L2) >= 2 → pop
  stack = [root(L0), "2.Methods"(L1)]
  挂到 "2.Methods".children
  stack = [root(L0), "2.Methods"(L1), "2.2."(L2)]

→ title "3. Data sets" (L1)
  flush: 段落 → "2.2.".own_text
  pop: "2.2."(L2) >= 1 → pop
  pop: "2.Methods"(L1) >= 1 → pop
  stack = [root(L0)]
  挂到 root.children
  stack = [root(L0), "3.Data sets"(L1)]
```

---

### 步骤 4：后处理——orphan text + page_range 合并

**情况 A：root.own_text 非空（文档开头有无标题文本）+ root 有 children**
→ 创建 `(Untitled Prologue)` L1 节点，插入 children 头部

**情况 B：root.children 为空 + root.own_text 非空**
→ 创建 `(Untitled Document)` L1 节点

**情况 C：root.children 为空 + root.own_text 也空**
→ 创建 `(Empty Document)` L1 占位节点

**page_range 合并**：递归将子节点的 page_range 合并到父节点。

**注意**：这里不做字数阈值切分。即使 section 有 50000 字也不管——SectionBuildStage 的职责到此为止。

---

### 步骤 5：合约收尾

```python
root.own_text = ""
root.title = ""
root.level = 0
root.page_range = [-1, -1]
```

确保 root 节点是纯容器，不含任何文本/标题。

## 4. 函数签名与接口约定

```python
def run_section_build_stage(
    content_list_v2: Any,
) -> SectionNode:
    """
    SectionBuildStage 唯一入口。
    
    输入:
        content_list_v2 — MinerU 产出的结构化文档
                         支持 list[list[dict]]（标准）和 list[dict]（简化）
    
    输出:
        SectionNode — root 节点（level=0），其 children 是完整的 N 层 section tree
    
    职责边界:
        ✅ 收集文本 block（步骤 1）
        ✅ heuristic 推断 level（步骤 2）
        ✅ 标题栈建树（步骤 3）
        ✅ orphan text 后处理（步骤 4）
        ❌ 不做 token 估算
        ❌ 不做字数切分
        ❌ 不做 LLM 调用
        ❌ 不做过短 section 合并
    """
```

## 5. 内部模块分解

```
run_section_build_stage(content_list_v2)
│
├─ 1. 归一化输入 → pages: list[list[dict]]
│     扁平化遍历 → flat_blocks: list[FlatBlock]
│     └── _extract_any_text(block)
│     └── _is_title_block(block)
│     └── _should_skip_block(block)
│     └── _extract_title_text(block)
│     └── _get_title_raw_level(block)
│
├─ 2. resolve_levels(flat_blocks)
│     └── infer_level_by_numbering(text)  ← 12 种编号模式
│
├─ 3. 标题栈构建 tree → root: SectionNode
│     └── flush_text_to_top()
│
├─ 4. 后处理：orphan text + page_range 合并
│     └── _merge_child_page_ranges(root)
│
└─ 5. 合约收尾：root.own_text="" root.title="" root.level=0
```

## 6. Edge Case 完整清单

| # | 场景 | 输入特征 | 处理方式 | 输出 |
|---|------|---------|---------|------|
| 1 | 正常层级文档 | 有编号标题 "1." "1.1." | heuristic 推断 level | 多层 tree |
| 2 | 全 L1 + 有编号 | hybrid/vlm, "2.1."等 | heuristic 推断 level | 多层 tree |
| 3 | 全 L1 + 无编号 | hybrid/vlm, "Abstract"等 | 无编号→L1 | 扁平 tree |
| 4 | pipeline 后端 | raw_level 只有 1 和 2 | **不信任 raw_level**，heuristic 推断 | 正确多层 tree |
| 5 | 连续标题无间隔 | "2.Methods"后紧跟"2.1." | 父节点 own_text="" | 父有 children 但 own_text 空 |
| 6 | 完全无标题 | 全是 paragraph | 所有文本 → sole section | 1 个 section |
| 7 | 标题稀疏 | 前 N 页无标题 | prologue section + 后续 | prologue + 标题 sections |
| 8 | 空文档 | 无文本 block | 空 section 占位 | 1 个空 section |
| 9 | 混合编号体系 | "I."+"A."+"1.1." | 各 pattern 独立匹配 | 正确嵌套 |
| 10 | 标题文本提取失败 | title block 但 content 异常 | title="(Untitled page X)" | 正常建树 |
| 11 | content_list_v2 非 list | 输入类型异常 | 强转为空 list | 空文档兜底 |
| 12 | level > 4 的标题 | heuristic 推出 5 层 | `min(len(parts), 4)` 截断到 4 | 最多 4 层嵌套 |
| 13 | 标题 level 跳跃 | L1 直接到 L3 | L3 挂在 L1 下 | L1 → L3（无 L2） |
| 14 | 纯自然标题文档 | 完全无编号，全部 inferred=None | 走 raw_level 兜底 | 保留相对层级 |

## 7. 与 SectionEnhanceStage 的衔接协议

**SectionBuildStage 保证**：
1. 返回的 root 节点 level=0，own_text=""
2. root.children 至少有 1 个节点（哪怕是空文档占位）
3. 每个 SectionNode 的 section_id 全局唯一（`sec_001` ~ `sec_NNN`）
4. own_text 只包含当前节点直属的文本，不含子节点文本
5. tree 中没有文本重复——每段文字只出现在一个节点的 own_text 中
6. children 列表的顺序与文档原文顺序一致
7. tree 的深度不超过 5（heuristic 限制 level ≤ 4 + root L0 = 5 层）

**SectionEnhanceStage 负责**：
1. 遍历 tree 做增强（按 enhance_depth 截断）
2. 处理 own_text 超长的 section（map-reduce）
3. 处理 own_text 为空的父节点（基于子节点结果汇聚）
4. 处理增强失败的容错（status=failed）
